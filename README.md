# Code City

Turn any git repository into a 3D city you can fly around. Directories become districts, files become buildings: footprint and height come from file size.

```
make build
./bin/codecity serve                                     # then enter a repo in the page
./bin/codecity serve .                                   # or start with a local repo
./bin/codecity serve https://github.com/expressjs/express --max-commits 60
./bin/codecity serve . --ref v1.2.0 --exclude 'docs/' --exclude '*.snap'
./bin/codecity serve https://github.com/expressjs/express https://github.com/expressjs/body-parser https://github.com/pillarjs/router
./bin/codecity analyze . -o city.json                    # just the data
./bin/codecity report https://github.com/expressjs/express > report.md   # Markdown findings for CI / PRs
./bin/codecity outline internal/server/server.go          # the pieces found in one file
```

Open http://127.0.0.1:8080. Type a local path or git URL in the panel and press Analyze; progress is shown and can be cancelled. Each repository gets a **branch picker** (branches, remote branches and tags, listed without cloning; *Other ref or commit…* takes anything git can resolve), and clicking the city's name (`repo · branch ▾`) switches the loaded city to another branch and re-analyzes it.

- **History:** the first-parent history up to the ref is sampled (default 100 commits). Use the timeline to scrub or play (space, arrow keys); buildings grow, shrink, appear and vanish. The layout never moves: footprints are fixed by each file's peak size. Green/amber tint = added/changed in that commit.
- **Several repositories:** enter one per line (optional ref after a space) or pass several on the command line. Each repo becomes its own city on one map. Cities are connected only when there is evidence: a declared dependency (go.mod, package.json, Cargo.toml, pyproject/requirements/setup.py, submodules, git URLs) and/or code that imports the other repo (Go, JS/TS, Python, Rust). Light flows along each arc from the dependent repo to its dependency; click an arc for the evidence and the importing files, or select a file to see arcs to the exact directories it imports. **Highways** join cities that talk over the network: *API calls* (a request in one repo matches a route another serves) in amber and *messages* (one repo publishes to a topic or queue the other consumes; Kafka, NATS, RabbitMQ, Redis pub/sub, MQTT, SQS/SNS) in green, as roads with light cars from rim to rim. Only literal URLs and topic names (or constants that resolve to one) are matched, and a call is linked only when one other repo clearly serves it. Click a highway for the calls or topics; select a file to see arcs to its counterparts. *Shared people* (contributors in both repos) is an optional second link type. The timeline merges all repos by date.
- **Code links:** imports between files of the same repo (Go packages, JS/TS relative/alias/workspace imports, Python modules, Rust modules) drawn as circuit traces on a raised data bus: cyan = what the selected file imports, magenta = who imports it; or the whole city at once (L cycles). The inspector lists imports / imported by, there is a *dependents* color mode, and the *Deps* tab ranks the most depended-on files and finds directories that import each other.
- **Flow view** (FLOW or D): a diagram of how the code runs, built by static analysis at the newest commit. Inputs come in on the left (HTTP routes served, CLI commands and flags, UI events and timers, environment, files read), code sits in the middle, and side effects leave on the right (processes such as `git`, files written, HTTP calls, SQL tables, browser storage, stdout/logs); amber boxes are state that functions write and others read. Three levels: the *system map* (modules and the traffic between them), a *module* (its functions plus what calls in and what it calls out), and a *mind map* around any function, route or table (callers grow to the left, callees and effects to the right; + knobs expand a branch, *Steps* follows further). Click a box for its source, its calls and callers with line numbers; click a line for the exact call sites. Frontend `fetch('/api/x')` calls are linked to the backend route that serves them, across repositories too. Go is analyzed with `go/types` (calls resolve exactly, interface calls reach their implementations); TypeScript/JavaScript, Python and Rust resolve through imports, class fields and scope, and calls matched only by a unique name are drawn dashed and can be hidden. `codecity flow <dir>` prints a summary.
- **Guided tour** (▶ Guided tour or U): a route through the codebase built from what the city knows — README and architecture notes, the manifest, entry points, the files that wire modules together, the most-imported modules (and their tests), hotspots, and files whose owner has gone quiet. Each stop says why it matters; N / B step, *Walk here* drops you in front of it in walk mode.
- **Story:** the inspector shows the commit that created a file (its message explains why it exists) and its latest changes (`/api/history`).
- **Walk mode (G, hacker mode):** explore as a little android. WASD + mouse (click to capture), Shift run, Space jump, V first/third person, E enter/use, Q exit, H help. Every building is a tower: lobby with a directory, one floor per function/class/method, switchback stairs and an elevator. Code is on the walls (wheel scrolls); aim at an identifier and click to get its definitions across the world, then ride a tracer there. Needs `codecity serve`.
  - **Fly** like Minecraft creative mode: double-tap Space to take off, hold Space to rise and Shift to sink, double-tap W to go fast; touching the ground (or double-tapping Space) ends the flight.
  - **Take a building apart** (X): its pieces float apart as floors you can fly between and stand on; aim at a floor and click to go inside at that piece. **I** opens a card: role, owner, origin commit, recent changes, pieces, imports / imported by.
  - **Map** (M) and minimap: fog of war (buildings you have studied light up), shards, quiz terminals and quest targets; click a building to travel there. **/** searches files and definitions and teleports you.
  - **Game:** XP and ranks (Intern → Architect) for studying files, quests generated from the repo (read the README, find the entry point, meet the core modules, take apart the main hub, trace definitions, read origin stories, visit the hotspots, cover every top directory), achievements, data shards in front of tour stops (gold ones on the roofs of core modules — fly up), and quiz terminals on each top directory asking real questions (*where is X defined?*, *which file imports Y?*) with a teleport to the answer. J shows quests and achievements; progress is saved per repository in the browser.
- **Hotspots:** change frequency × indentation complexity, the files where refactoring pays off most.
- **Change coupling:** files that keep changing in the same commits. Select a file to see glowing arcs to its partners.
- **Knowledge risk & owners:** owner (most commits) per file, author count, owners who have gone inactive. Click a person to light up their files.
- **Code age, complexity, compare:** color by time since last change, by complexity, or by growth since a baseline commit (shift-click the timeline).
- **Insights panel:** Hotspots / Coupling / Risk / Complex / Areas / People, all clickable, plus *Copy report as Markdown*.
- **Inspector:** metrics, history sparkline, ownership, coupled files, GitHub / VS Code links. Click a directory for its stats. Deep links: the URL hash keeps the commit, color mode and selected file.
- **Pieces:** a selected file lists its classes, functions, methods and types (lines, complexity). *Explode* (E) splits the building into floors, one per piece; click a floor or list entry to read that piece's source at the current commit ([ and ] step through pieces).
- **Building architecture** (Buildings: architecture / classic boxes, or B): each building is built from its code, never at random. *Shape*: the file's big declarations become setback tiers (a class with its methods is a tower on a podium; many small functions make a slab; types only, a glass box; data, a utility block; docs, a library; tests, a lattice). *Facade*: the language (Go concrete, TS/JS glass, Python brick, Rust steel, HTML/CSS storefronts). *Rooftop*: what the code does, from the flow analysis (spire = entry point, dish = serves HTTP, tanks = database, chimney = runs processes, vents = files, uplink = calls HTTP services; the most-imported files get a columned lobby). *Condition*, per commit: scaffolding and cranes for recent heavy churn, irregular windows for complex code, weathering for old code. The inspector's "Why it looks like this" and the legend explain each one. *Test walkways*: a lit skybridge joins each test to the code it tests (walkable). In walk mode the setbacks are terraces you can climb; press E on a landmark's roof to read what it does (quest "Skyline tour").
- **Hacker mode** (`>_` or H): black void, glass towers of glowing scrolling data, a magenta circuit-board floor; the selected building wears its own source code. Color modes still apply.
- Day/night themes (T), search with jump (/ then Enter), F for overview, Esc to step back.
- Orbit with the mouse, hover for details, click a building (with a LOC sparkline), search to dim non-matches, change height metric / scale / color. You can also drop a `city.json` onto the page.

Requirements: Go 1.24+, git, Node 20+ (to build the viewer).

Notes
- Only committed content is analyzed; uncommitted changes are ignored. History follows first parents (merge commits count as one step, but churn includes the merged commits).
- URLs are fully cloned for history/churn, which can be slow and large for big repos; use `--max-commits 1 --no-churn` (or untick "churn & hotspots" with 1 sample) for a fast shallow snapshot.
- Renames show as a delete plus an add (files are identified by path).
- When the server is bound to a non-loopback address, the page can only analyze remote URLs, not local paths.
- Skipped by default: vendored dirs, lockfiles, minified, binary, generated, symlinks, submodules, files over 2 MB. Use `--include-vendored` / `--include-generated` to keep them.
- `go install` alone produces a binary without the viewer; use `make build` (or `--web-dir web/dist`).
