# Code City

Renders any git repository as a 3D city: directories are districts, files are buildings.
Go CLI does the analysis and emits `city.json`; a Vite + three.js viewer renders it and is embedded in the Go binary.

## Layout
- `cmd/codecity` – CLI (`analyze`, `serve`, `version`)
- `internal/gitx` – shells out to `git` (all calls take a `context`); reads blobs from objects at a commit (`ls-tree`, `cat-file --batch`), never the working tree; also first-parent `Log` and per-range `Churn` (`log --numstat --no-renames -z`)
- `internal/scan` – file filtering (vendored, lock, minified, binary, generated, large) + LOC + language
- `internal/layout` – squarified treemap (deterministic: ties broken by name). Siblings that carry a `Bias` signal (from `analyze/gates.go`: -1 = only takes things in — routes, commands, events, program entry; +1 = only reaches out — database, network, files, processes, other services) switch to ordered rows laid from the top, so entrance files and directories sit toward the north edge of their district and exit files toward the south; directories average their children's bias. The city's doors are part of its layout, and the world map (`arrange.go`) flows the same way
- `internal/city` – `city.json` schema (version 8; `Link.Via`/`Brokers` for highways, kinds `dependency|people|api|message|data`; `Building.Imp`/`ImpD` = same-repo imported files / package dirs; `Repo.Base`/`RepoInfo.Base` = a monorepo project's git-relative dir); `City.Facts` (json:"-") carries per-repo linking facts server-side; `web/src/types.ts` must mirror it (`SCHEMA_VERSION`)
- `internal/messaging` – heuristic scan for message topics a file publishes/consumes (Kafka for Go/JS/TS/Python/Rust; NATS, RabbitMQ/AMQP, Redis pub/sub, MQTT, SQS/SNS via first-argument call patterns). Only literal topics or names that resolve through a repo-wide constant map (conflicting definitions dropped) count; tests are skipped. Also Java/Kotlin (@KafkaListener, KafkaTemplate, @RabbitListener, @SqsListener, JMS), C# (Confluent, RabbitMQ.Client, ServiceBus) and AsyncAPI files (v2 publish = app consumes, v3 action send/receive)
- `internal/netscan` – network facts from non-Go/JS-flow languages and config: Spring/JAX-RS/ASP.NET routes, JVM/C# HTTP clients + base URLs, Retrofit, WebSocket clients, gRPC servers/clients (pseudo-route `/grpc/<Service>`), GraphQL schema/operations (`/graphql/<Query|Mutation|Subscription>.<field>`, schema routes weak without a server marker), env-var URLs (resolved via .env/compose/k8s/Dockerfile, else a host hint from the variable name), compose/k8s service names as repo aliases, OpenAPI specs (weak routes)
- `internal/analyze` – glue (`shape.go`: per-file `Building.Shape` = setback tiers from dominant declaration groups, archetype, and rooftop roles from a flow run at the newest commit): repo → sampled commits → per-file size/complexity history + churn → flow graph of the newest commit (`readFlow`, reused for roles and highway facts) → one layout over every file ever seen, biased by entrances/exits → `City`; `links.go` records per-repo highway facts (`Facts.Serves` routes from the flow graph, `Facts.Calls` requests, `Facts.Messages` topics); `churn.go` adds owners (case-insensitive author merge) and change coupling. `RunRepoN` scans the repo once then, when `Options.Split` is set and `monorepo.go` finds ≥2 projects (dirs with a build manifest), emits one city per project (paths rebased to the project root, flow/facts/churn/people scoped to it) plus a "root" city for leftover files — all sharing one clone; `RunAll`/the server hand these to `workspace.Build` so the projects link as highways like separate repos. `Run` stays one-city (used by tests)
- `internal/deps` – what a repo provides (Go module, npm/crate/Python names, git remote, Python packages) and uses (manifest deps: go.mod, package.json, Cargo.toml, pyproject/requirements/setup.py, .gitmodules; code imports for Go/JS/TS/Python/Rust); `local.go` resolves imports *inside* a repo (JS/TS relative + `@/` aliases + workspace packages, Go module packages → directories, Python absolute/relative modules, Rust `mod`/`crate::`/`super::`)
- `internal/workspace` – multi-repo worlds: links repos by evidence (dependency = manifest match and/or imports, with importing-file → imported-directory pairs; people = shared contributors, bots ignored; `highway.go`: **api** = a request matches a route another repo serves (`flow.Match`, most specific route wins, linked only when exactly one other repo serves it or the request's host names the repo; generic routes like /health ignored; own routes never link), **message** = same broker + topic published in one repo and consumed in the other, publisher → subscriber), arranges cities from facts alone (`arrange.go`, deterministic, independent of input order: connected repos form regions laid out in north→south layers — callers/publishers/writers/dependents north of what they use, longest-path layers, entrances tightened toward their targets, barycenter ordering, cities pulled toward neighbours; unlinked regions are islands packed first-fit on a spiral; every pair keeps a margin for roads), merges into one City (world root district 0 at depth -1, repo roots are its children, paths prefixed with the repo name, timelines merged by date and **deduped by commit hash** so a monorepo's project-cities share one timeline, authors merged case-insensitively)
- `internal/analyze/monorepo.go` – `detectProjects` finds project roots (dirs that directly hold a manifest via `deps.IsManifest`; the repo root is always a leftover bucket); `groupPaths` assigns each file to its deepest project. Split only happens when ≥2 projects end up with files
- `internal/outline` – heuristic per-language outline (types, functions, methods, gaps as imports/scope) used for a file's "pieces"; `codecity outline <file>` prints it
- `internal/flow` – flow graph (version 1): nodes func/method/class (code), endpoint/command/flag/event (inputs), io (outside world, `Sub` process|file|http|db|storage|env|stdio|log|network|args|stdin; shared across repos), data (state); edges call/new/ref/impl/handles/feeds/writes/io/request with call-site `Lines` and `Exact`. Go: `go/parser` + `go/types` with stubbed non-repo imports (`golang.go`; receiver/package-var/captured-variable writes only count as state; routes via HandleFunc/Handle/gin-style methods incl. local closure handlers; CLI via `switch os.Args`/cobra; stdlib I/O table). JS/TS (`script.go`), Python (`python.go`), Rust (`rust.go`): token-level analyzers (`tokens.go`) resolving via imports, class/`self` field types, typed locals, CommonJS owners; name-only fallback must be unique, imported and not a builtin name. `finish` links requests to the most specific served route (cross-repo), drops never-written state. `BuildAll` = one graph for a multi-repo world; `codecity flow <dir>` summarizes a working tree
- `internal/insights` – findings at the newest commit (hotspots, coupling, knowledge risk, complexity, areas) + Markdown; used by `codecity report`
- `internal/server` – HTTP server + job API (`/api/status`, `POST /api/analyze`, `POST /api/cancel`, `/api/city`, `GET /api/file?path=&commit=` → content + pieces, `GET /api/symbols` → lazily built definition index `[name, kind, path, start, end]` at each repo's newest commit, `POST /api/refs {source}` → branches / remote branches / tags + default branch (for-each-ref locally, `ls-remote` for URLs, no clone; POST so the Origin check applies), `GET /api/flow` → the flow graph at each repo's newest commit (lazily built, cached per loaded city, gzip), `GET /api/history?path=&n=` → the file's commit that added it (`created`) + newest non-merge commits (bodies without trailers) + total). `POST /api/analyze` takes `sources` ("source [ref]" per entry, ≤12) and `split` (split monolithic repos into project-cities) and builds a workspace; project-cities of one repo share its clone (file reads re-add `Repo.Base` to the git path; a commit is accepted for any city sharing the same clone); file reads map merged paths back to (repo, path) and only accept that repo's commits. Keeps the analyzed repo open (temp clones are removed on the next analysis or ctrl-c); file reads are limited to paths and commits of the loaded city. Loopback-only Host/Origin guard; local paths only accepted when bound to loopback
- `internal/web` – `//go:embed all:dist` of the built viewer
- `web/` – viewer (plain three.js, TypeScript, no framework): `scene.ts` (rendering, picking, camera), `material.ts` (window/hacker/glow shader + circuit floor), `theme.ts` (night/day/hacker + procedural glyph/circuit/code textures), `code.ts` (source viewer), `links.ts` (TraceLayer: batched circuit-trace ribbons with flowing pulses; `busRoute` = raised data bus above the skyline), `fx.ts` (hacker atmosphere: floor tracers, particles, hotspot beacons), `walk/` (walk mode: `avatar.ts` original cute android, `trail.ts` light trail, `interior.ts` building interiors, `codewall.ts` code walls + clickable panels, `map.ts` minimap + full map with fog of war, `game.ts` XP/ranks/quests/achievements/quiz questions (localStorage per repo, keyed by path), `panels.ts` HUD DOM (status, rewards, card, tour, quiz, search, quest log), `props.ts` data shards + quiz terminals, `walk.ts` controller), `flow/` (flow view, its own full-screen SVG UI: `model.ts` lanes/filters/adaptive module groups/system map/module view/mind map, `layout.ts` layered layout + two-sided tree, `view.ts` toolbar, index of ways in/out, pan/zoom, knobs, pulses, source panel), `branches.ts` (branch rows under the source box — picking rewrites that line to "source ref" — and the branch switcher on the city name), `tour.ts` (guided tour: docs → manifest → entry points → hubs → core modules + their tests → hotspots → knowledge risk; used by the overview and walk mode), `insights.ts` (mirrors `internal/insights` for the current commit), `ui.ts` (DOM), `main.ts` (wiring, jobs, deep links)

## Architecture (building shapes)
- Buildings differ by their code, never at random. `web/src/architecture.ts` turns `Building.Shape` into one `BuildingSpec` (tiers, facade, roof pieces, plinth) shared by the night/day renderer, hacker mode and walk mode. `roofs.ts` is the rooftop kit (role equipment, scaffolding and cranes for recent churn). Tier 0 is `buildingMesh` (instance = building index); upper tiers are `tierMesh` (`tierOwner` maps back). Facade/condition go to the shader via the per-instance `aFacade` = (style, irregularity, age, seed). Condition (`updateCondition`) is per commit; shape is from the newest commit only.
- Language → facade: Go concrete, TS/JS glass, Python brick, Rust/C steel, HTML/CSS storefront, docs library, data utility; tests lattice; types-only glass box. Roles: entry spire, serve antenna, db tanks, exec chimney, files vents, call uplink.
- Docs libraries: a prose-only folder (every file Markdown/Text, `docsDir` in `analyze/analyze.go`) collapses into ONE "library" building (archetype `doc`) instead of a district of tiny doc buildings; its synthetic history sums the documents and it carries `Building.Docs` (name/path/lang). The side panel and the walk-mode interior (one "Documents" floor) list the documents; clicking one opens its markdown in the code viewer. The server registers each doc's path for `/api/file` even though the docs aren't buildings.
- Test walkways (`web/src/walkways.ts`): a skybridge joins each test file to the code it tests (its imports and same-named sibling: `foo_test.go`↔`foo.go`, `foo.test.ts`↔`foo.ts`, `test_foo.py`↔`foo.py`), ≤2 per test, only where the footprints face each other across a short gap with nothing in between. The deck lies at the lower podium roof (`podiumTop`); decks are walkable (`walkData().solids` with `i: -2`; `-1` means no exploded building). Hidden with "classic boxes".
- Walk mode collides with `walkData().solids` (tiers: setbacks are terraces); `boxes` stay one per building. "Buildings: classic boxes" (B) = `scene.setClassic`.
- Storeys (interior levels and exploded floors) are stacked by tier like the outside: podium pieces first, then each tier's (`tierOfFloors`, file order within; `byTier` in main.ts). Interiors (`InteriorSpec.arch`) wear the facade's finish (wall pattern + accent), a tier-colored band per storey, a setback outline + terrace on set-back tiers, and a ROOF sign under the ceiling. E on a landmark roof explains its equipment (`useRoof`; quest "Skyline tour").

## Commands
- `make build` – builds viewer, copies it into `internal/web/dist`, builds `bin/codecity`
- `make test` / `go test ./...`
- `cd web && npm run dev` – viewer dev server (proxies `/api` and `/city.json` to a running `codecity serve` on :8080)
- `cd web && npm run typecheck`
- `make demo` – serves twelve example services (`examples/highways`: REST, Kafka, gRPC-less mix, Java, GraphQL, WebSocket, OpenAPI/AsyncAPI, shared DB table) as one world; `scripts/demo-highways.sh highways-lang` serves the multi-language world (FastAPI, Rust, C#, gRPC, Flask); `TestExampleHighways*` and `TestApiLinksAtScale` check them
- `cd web && npm test` – road geometry and gate tests (`src/roads.test.ts`, `src/gates.test.ts`, node type-stripping)

## Conventions
- Go: stdlib only. Keep git access in `gitx`; validate refs (no leading `-`), use `--` before user-supplied URLs.
- Built viewer files in `internal/web/dist` are git-ignored except `.gitkeep`, so the embed always compiles; `go install` yields a binary without the viewer (use `make build` or `--web-dir`).
- Changing the `city.json` schema: bump `city.Version` (now 8), update `web/src/types.ts` (`SCHEMA_VERSION`) and the viewer's `isCity` check.
- Layout stability: footprints come from each file's *peak* LOC over the sampled history and never change between commits; per-commit size is `Building.H` (change points, loc -1 = absent). Don't recompute layout per commit.
- Identity is the path: a rename shows as delete + add (churn uses `--no-renames` for the same reason).
- Churn bucket i = non-merge commits in (sample i-1, sample i]; bucket 0 = everything up to the first sample. Needs a full clone, so URLs are shallow-cloned only for `--max-commits 1 --no-churn`.
- Complexity = indentation complexity (Tornhill): per non-blank line, tabs + spaces/4. Hotspot = churn commits × complexity. Docs/data/config languages are excluded from hotspots/complexity rankings (`NON_CODE` in `scene.ts`, `NonCode` in insights).
- Coupling: co-change pairs from non-merge commits touching ≤30 files; keep pairs with ≥3 shared commits and degree ≥25% (shared / mean revisions), top 8 per file.
- Knowledge risk: owner = most commits to the file; "owner inactive" only when the owner hasn't committed for 180 days *and* holds ≥50% of the file's commits or there are ≤2 authors. Keep TS (`scene.risk`) and Go (`insights`) rules identical.
- Floats in `city.json` are rounded to 3 decimals.
- Angular components (if any are ever added): never use inline templates or inline CSS.

## Viewer notes
- Exploded view: floors = top-level pieces with containers replaced by their members (`floorsOf` in main.ts); floor height ∝ LOC, color ∝ complexity density.
- Hacker mode is a theme (`THEMES.hacker`, `uHacker` in shaders): text atlas built from repo names, circuit traces in world space, selected building wears its real source (`setSkin`). Keep color modes meaningful in it (text is tinted by the mode color).

- Highways (`api`, `message`, `data` = shared DB table with a writer, writer → reader): drawn as asphalt strips (`highwayMaterial`) from the rim of one city to the rim of the other, lit edges and light "cars" (api: both lanes, the return lane dimmer; message: one way). Several highways between the same cities sit side by side; a road goes around cities in its way (straight, else L-shaped, else a dog-leg past the blockers: `highwayRoute`). Link toggles: API calls / messages / databases. Pure route geometry lives in `web/src/roads.ts`. Clicking a highway lists its calls or topics; a selected highway or file draws arcs between the buildings behind it (`viaArcs`). Amber = api, green = message, purple = data. Walk-mode map draws them too.
- Doors ("entrances & exits" toggle, needs the server): `gates.ts` turns the flow graph into gates — entrances = routes/commands/flags/events handled by code, env/args/stdin inputs, program entry points; exits = io nodes (db, http, storage, process, file, network; log/stdio ignored) reached from code, plus requests to another service's route. `layoutGates` merges doors of the same flow node into one `EdgeGate` and stands it on the edge of its city (entrances north, exits south, as near as possible to the files behind it, never overlapping; deterministic). `gatemarks.ts` draws the arches (teal in, coral out; `Pick` kind `gate` = index into the edge gates). Clicking a gate (or selecting a building with doors) draws streets (`showGateStreets`, a `TraceLayer`: ramp at the gate → over the skyline → onto the roof; entrances flow gate → file, exits file → gate) and the panel lists the files with `flow` (`FlowView.focusId`) and `code` (piece containing the line). The flow graph is fetched once per city (`flowGraph()` in main.ts, shared with the flow view). `traceRoute` follows one entrance through the code (handler → callees in call order → each way out, one stop per file); "Follow the route" (or `route` per file for merged gates) walks it stop by stop in the city (street to each stop, code open at the line, ←/→). Doors are on by default when the server is available (toggle remembered). Dozens of doors of one kind (DOM events, flags, tables) collapse into one gate with the list in its panel. Walk mode: aim at an arch + click/E (it glows, then a menu lists each route/table/host behind it with file:line) or press R (entrances, paged; a collapsed gate lists each of its routes) — `WalkHost.doors/leadsOf/doorRoute`; N/B step the route (teleport to the line in each file, stops on the map); arches stand on the city edge as in the city view.
- Multi-repo: a city exists only from its first sampled commit on the merged timeline. Connection arcs use a flow shader (pulses travel from the dependent repo to its dependency); selecting a file also draws its cross-repo import arcs. Only evidence-backed links are drawn; unrelated repos stay unconnected.

- Code links (imports inside a repo) are drawn on a raised "data bus": up from the importer's roof, orthogonally across above the skyline, down onto the target (ground traces were hidden by the dense treemap). Modes: selected file (cyan out / magenta in), whole city (file edges ≤350, else bundles between directories), off. Go package imports reach every file of the package except `_test.go`.
- Walk mode (G; forces hacker theme and the newest commit): outdoor player height = 0.6 × `scene.cell` (≈ 1/5 of a median building's width; streets come from `layout.DefaultOptions` gaps); WASD moves relative to the camera and the body turns to face its walking direction (`heading`); street-level bloom is calmer (`scene.setStreetLevel`). Player physics outdoors use building AABBs (low roofs are steppable) and district plates; interiors are separate scenes (`scene.setView`) with their own calmer bloom. Interior layout: 16×16 plate, storey 4.5, level 0 lobby (directory + file info), level k = floor k (floorsOf), switchback stairs on the east lanes, elevator in the SW shaft, code wall on the north wall (lazy per level ±1), references panel on the west wall. Teleports: same building = tracer ride inside; other building = tracer along `busRoute` over the city, then enter at the floor containing the line, highlighted.
- Walk-mode extras: flight follows Minecraft creative rules (double-tap Space toggles; Space up, Shift down, double-tap W sprint — no Ctrl, Ctrl+W closes the tab; landing ends it; not indoors). X explodes the focused building in place (`scene.explode(i, floors, false)`); its floors replace its collision box (`scene.explodedBoxes()`), so you can stand on them; click a floor to enter at that piece. Focus = aimed building, else the building you just travelled to, else the facade in front of you. Shards: one in front of each tour stop (a few steps from the landing spot), gold ones on the roofs of the 3 most-imported modules. Quiz terminals sit in each top directory's padding strip. Game progress is stored by path, never by building index.
- Flow view (FLOW button or D; Esc / D / "Back to city" closes; the 3D scene is paused while it is open): lanes in → code → out, colors by role (teal inputs, ink code, amber state, coral side effects, magenta requests). System map groups modules adaptively (split the biggest directory while it holds >12% of the code, ≤32 groups); loops against the main direction are faint until hovered. Mind map: right = where the flow goes next, left = where it comes from; outputs and state are traced backwards. Name-only call edges are dashed.
- The player avatar is an original design ("Bit"); do not model it on existing characters.
